# The bikefree toolbox

Every route is built from one shared set of kits. A route is a **scene JSON** that turns kits on and gives them
the place's data (palette, species, distances, landmarks). Code is never written for one route only: a new
feature goes into the toolbox behind a scene field, so the next route can use it too.

- **Code:** `js/world/toolbox/` (the kits) and `js/world/` (the engine that assembles a scene)
- **Scene fields:** `js/world/toolbox/scene-schema.js`, checked by `npm run lint:scenes`
- **Models:** `tools/toolbox-gallery.html`, rendered headlessly by `npm run gallery`
- **New route:** `npm run new-route -- <id> --preset <biome>`, starting from `routes/presets/`
- **Refactor safety:** `npm run guard`, which checks that every route still builds identically
- **Step by step:** the new-route guide (the Project doc `claude/new_route.md`), then `ROUTES.md` for the full field reference

## The standard for new routes

Decided 16 Nov 2026. Every biome preset already has it:

| | Standard |
| --- | --- |
| Look | gentle |
| Light | `"lighting": { "baked": "midday" }`: a fixed sun with baked shadows and AO. One time of day per route, `"timeOfDay": "midday"` |
| Camera | Chase only |
| Distance | Vista kit (`"vista"`) wherever there are mountains or long views |
| Planting | A regional pack (`"packs"`) when one fits the region. Species, palette and buildings come from the real place |
| Scale | Trees at full height, ground cover below the knee, boulders 1–2 m |
| Budget (Balanced, M4 Air) | Under 600 draw calls and 2M scenery triangles |

The six routes made before the toolbox keep their own look for now. The linter lists what each is missing.

## Start a route

```sh
npm run new-route -- --list                       # the presets
npm run new-route -- ventoux --preset mountain --name "Mont Ventoux" --park "Bédoin → summit, Provence" \
  --waypoints "44.124,5.178;44.174,5.278" --km "21,22" --one-way
```

The command does all of this:
- creates the branch `<id>-test`
- writes `routes/scenes/<id>.json` from the preset
- adds the catalog entry under **Rough Drafts**
- appends a `PLAN.md` section with the workflow as a checklist
- writes `docs/<id>/REVIEW.md`
- prints the road and terrain commands to run next

| Preset | Built from | Terrain tool | Kits switched on |
| --- | --- | --- | --- |
| `forest-lake` | Route 28 | `build_scene_terrain.py` (USGS + lakes) | northeast pack, forest-edge planting, lake water, villages and camps, utility poles |
| `mountain` | Going-to-the-Sun | `build_terrain_grid.py` (10 m / 40 m) | northern-rockies pack, vista kit, weather, road surface, verge, mountain-road structures, traffic |
| `coast` | Big Sur | `build_terrain_grid.py` | real shoreline and surf, arch bridges, coast life, traffic, marine layer |
| `city` | Pittsburgh | `build_city.py` + `build_terrain_grid.py` | city kit: streets, facades, junctions, riverfront, bridges, people and traffic |
| `desert-canyon` | Zion | authored landforms | Blender regional kit, formations, valley |

Presets are generated by `node tools/build_presets.mjs` from the finished routes' look blocks. Everything placed by distance or tied to the place is left out, and the standard is laid on top. Don't edit the generated files. `npm test` fails if they're stale.

## Layout

```
js/world/                    engine: assembles a scene from the toolbox
  world.js                   renderer, camera, time of day, sun, frame loop
  stylized-terrain.js        scene builder: ground patches, plant scatter, forest tiles, sea, lakes, clouds;
                             loads kits and packs and switches each toolbox part on from its scene field
  terrain.js                 streamed real horizon and wireframe terrain (AWS Terrain Tiles)
  pose.js  rider.js  road-align.js  geo.js  terrain-data.js  perf.js
js/world/toolbox/
  scene-schema.js            every scene field, which module reads it, old-name mapping (normalizeScene)
  core/                      shared building blocks
  landscape/                 the ground under the road
  materials/                 procedural surfaces
  packs/                     regional model packs, plus the bundled Blender kits
  vegetation/                planting
  structures/                built things
  roadside/                  things beside the road (and the start / finish arches the app places per ride: course-arches.js)
  atmosphere/                look, light, weather, distance
  life/                      things that move
  city/                      the city kit
```

### core: use these in every new kit

| Module | What it gives you |
| --- | --- |
| `core/model-builder.js` | `Builder`: low-poly, vertex-coloured, flat-shaded models merged into one geometry. `M()` transform, `cyl` `cone` `blob` `box` primitives, `withSmooth()` for the gentle look's smooth crowns. Every regional pack and mountain-road structure is built with it. |
| `core/mesh-builder.js` | `MeshBuilder`, `ribbon`, `resample`, `makePath`, `hash`: indexed geometry along paths. Used by the city kit, traffic, wildlife, verge and visitors. |
| `core/random.js` | `randomSequence(seed)`: seeded, so a scene builds the same every time. Never use `Math.random` for placement. Also `smoothstep`, `vnoise`/`vhash` (planting patterns), `ROAD_CORRIDOR_M`. |
| `core/jobs.js` | Jobs: long builds as generators that pause at `due()` (`each`, `mapJob`, `mapGen`), run all at once (`drain`) or in frame slices (`runSlice(job, ms)`; `yield { wait: promise }` to wait). The same steps in the same order either way, so the result is the same: the city's areas are built this way on the ride (PLAN F30, `tools/area_build_check.mjs` proves it). |
| `core/pools.js` | `InstancePool`, `GroundBlocks`, `packMatrices`: one instanced draw per plant kind per quarter around the camera. |

### Landscape: the ground (`"terrain"`)

| Value | Module | Use for |
| --- | --- | --- |
| `real-mountain`, `real-coast` | `landscape/real-terrain.js` | Real elevation grid with the road pressed in, gorges bridged, creeks traced. The coast adds the sea and the shoreline. `glaciers`, `burns`, `streams`, `lakeIslands`, `sites`. Mapped land cover (`placesFile`) decides forest, meadow, farmland, rock and village ground where the map has it. On switchbacks the ground between two legs is one bank from road edge to road edge, and the inside of a tight turn sits at the lower side's level. |
| `authored-region` | `landscape/authored-region.js` | Baked USGS grid + lakes (`terrainData`) or authored `formations`, `lakes`, `rivers`, `valley`. |
| `authored-coast` (default) | `landscape/authored-coast.js` | An authored `coastline`. |
| `authored-city` | `city/landscape.js` | City data from `build_city.py`. |
| `wireframe` | `terrain.js` | Road and wire terrain only (a new route before its scenery, 2b in the workflow). |

`groundMesh: { "fineCells": 32 }` draws the ground patches that hold a switchback at 3 m instead of 6 m, so tight hairpins keep the road clear of the ground (QC checks the same mesh).

### materials

| Module | Scene field | What it does |
| --- | --- | --- |
| `materials/surfaces.js` | `palette`, `water`, `vista` | Ground shader: palette by slope, height, shore and canopy, with vista detail far off. Also sea, lake water, lake mist, and scenery decorations (wind on soft plants, foliage, concrete). |
| `materials/road-surface.js` | `road` | Road kind by stretch: fresh, worn, patched, chip seal, alpine, frost-heaved, tunnel, brick (running bond across the road), wet. Costs no draw calls. `markings: "fr"` draws the paint in metres by the French rules (T1 centre 3/10 m, T2 edges 3/3.5 m, short dashes and no edges in villages, solid centre on blind bends with T3 warning dashes, no paint on narrow roads) and adds aggregate, mottling, the paving seam and edge repair strips. A city route's trail stretches take their own `road.trail: { surface, zones }`. |
| `materials/stonework.js` | (used by structures) | `makeMasonryMaterial({ stones })`: rubble masonry in world space for walls, parapets and portals. |

| Blender `coastal.json` | `"assets"` | Big Sur first | cypress, pine, shrubs, rocks, outcrops, grass, flowers, succulent, poppy, lupine, bench, bridge |
| Blender `regional.json` | `"extraAssets"` | all early routes | broadleaf, fir, palm, yucca, sage, fern, alpine flowers, viaduct |

**Adding a pack:**
1. Write `packs/<region>.js` with the model builder. Export `make<Region>Pack({ fall, smooth })`, which returns `{ name: geometry }`.
2. Describe it in `packs/meta.js`: aliases, region, `variants`, `groundcover`, `models` by group.
3. Register it in `packs/index.js`. Add `decorateNear` if its trees have a surface shader.
4. Run `npm test`. It checks that `meta.js` lists exactly what the pack builds.
5. Look at it with `npm run gallery`.

### Vegetation (`"vegetation"`)

| Module | What it does |
| --- | --- |
| `vegetation/forest.js` | The `forest-edge` layout: a continuous canopy past a mown verge, in nested near ⊃ mid ⊃ far tiers so trees never jump. Mountain species come from data, `vegetation.zones`: bands by elevation with shady, sunny and wet mixes, alpine and broadleaf lists, and roles mapping the planner's needs (snag, log, krummholz…) to the pack's models. | `vegetation/tree-cards.js` | Far tree cards: camera-facing silhouettes that carry the forest past the real trees (Balanced and High). |
| `stylized-terrain.js` (scatter) | Other layouts: plants scattered per tile from `trees`, `shrubs` and `cover`, with ground-cover tiles near the camera. |

## The building kit (`"buildingKit"`)

Added 17 Nov 2026 (branch `buildings-test`), first on Alpe d'Huez. It sits on top of `structures/footprints.js`: the same footprint plan (what is kept off the road, the tree clearings), drawn by the kit when a scene has `buildingKit`. Without it, `footprints.js` draws the plain extrusions as before.

| Module | What it does |
| --- | --- |
| `buildings/presets.js` | Surface codes, window sets and the regional style presets: `provence`, `hautes-alpes`, `dauphine`, `oisans`, `ski-resort`. A style lists archetype weights, colour schemes (wall, shutters, frames, accent, roof together), wall, upper-storey, gable and barn materials, roof materials and shapes, pitch and eaves, and how often each extra and dressing item turns up. |
| `buildings/recipe.js` | Pure planning: drops duplicate map footprints, cuts L/T/U outlines into rectangles (cross gables), picks the archetype from size and density (cottage, village house, farmhouse with a barn end, chalet, mazot, block, shed, church…), floors, materials, roof, windows, the front (the wall facing the road) and the extras. Age, upkeep and wealth per building drive weathering and ornament together. Neighbours within 30 m never share a colour scheme; nothing that sticks out may reach the road or another building. |
| `buildings/assemble.js` | Geometry: walls in zones (stone plinth, body, timber upper storey, gable), thick roof slabs (gable, half-hip, hip, shed, flat with parapet, crow-stepped), wings, balconies and galleries, dormers, chimneys and stove pipes, lean-tos (open woodsheds), garages, outside stairs, génoise, bell towers, solar panels, painted sundials, a tent church. Near detail (door steps and canopies, gutters and downpipes, ridge caps, shop awnings) goes to a second mesh. |
| `buildings/facade-material.js` | One material for everything, so a stretch of village is one draw call. Walls: render, rough render with stone showing through, rubble, ashlar, brick, lap and vertical boards, logs, shingles, half-timber, metal, concrete, glass. Roofs: canal and flat tiles, fish-scale tiles, slate, lauze, standing-seam metal, corrugated, wood shingles, gravel. Windows by set (French casement, farm, chalet, resort, church, barn, sash) with frames, muntins, curtains, reflections, shutters open/closed/missing, sills, painted surrounds and flower boxes; doors, barn doors, shopfronts with sign bands, quoins, ivy, damp at the foot, drips, moss on shady roofs. Every detail fades to its average under ~2 px. |
| `buildings/dressing.js` | Ground dressing near the road, placed clear of the road and other buildings: pots and a bench by the door, bins, shrubs, a woodpile, hay bales by barns, a vegetable garden with a fence, a washing line, a satellite dish, a trough in village squares. |
| `buildings/kit.js` | `BuildingKit`: main meshes per 1 km stretch (in the bake), near detail per stretch built as the rider nears it (time-sliced, nearest first, not in the bake), culling. |

```json
"buildingKit": {
  "detailM": 120, "dressingM": 70,
  "styles": [
    { "fromM": 0, "toM": 4800, "preset": "provence", "stone": "#c9b89a" },
    { "fromM": 4800, "toM": 46000, "preset": "hautes-alpes", "stone": "#b9b2a3" },
    { "fromM": 125200, "preset": "ski-resort", "schemes": [ { "wall": "#ece6da", "trim": "#7a4f2e", "frame": "#6a4428", "accent": "#d8cdb8" } ] }
  ]
}
```

Any style key can be overridden per stretch (`schemes`, `walls`, `roofs`, `forms`, `pitch`, `balconies`, `dressing: { … }`…). A new region is a new preset in `presets.js` (data only).

**In a city** (`authored-city`, Pittsburgh first): with `buildingKit` in the scene, `city/city.js` hands its homes to `CityBuildingKit` (`buildings/kit.js`). Row houses (city kind 0) and houses (kind 1) that the street kit doesn't dress are drawn by the kit, and their main meshes fold into the city's 960 m sectors. Fronts face the nearest street (`makeStreetIndex`: every street plus the route, with clearances measured from the street's edge and sidewalk). Full shapes and dressing are tiered by distance to the route, and lamps and street trees keep clear of the kit's eaves, porches and dressing (`occupied()`). Every other city building keeps its own geometry and street-kit trim, but its facade gets the kit's surfaces through `FACADE_GLSL`: brick, stone, painted brick, concrete or metal by kind, weathering, and windows on the same grid as before with frames, sashes, blinds, curtains, lintels and sills (`cityFacades: false` turns that off).

```json
"buildingKit": { "detailM": 150, "dressingM": 80,
  "styles": [ { "preset": "pittsburgh-rowhouse", "kinds": ["rowhouse"] }, { "preset": "pittsburgh-frame", "kinds": ["house"] } ] }
```

Styles can be picked by map kind (`kinds`) instead of by stretch. **Added for cities:**
- **Presets:** `pittsburgh-rowhouse` (brick rows, stone lintels, stoops, side-gabled or flat with a bracketed cornice, front dormers) and `pittsburgh-frame` (painted siding, steep front gables, deep front porches).
- **Rows:** `attached` styles find party walls (blank, no eaves past them) and turn the ridge to run along the street.
- **Front porches** on posts with a railing and a shed roof.
- **Asphalt-shingle roofs.**
- **The `lintels` window flag.**

**Look at it:** renders a street of every preset (`street`, `aerial`, `close`, `roofs` views) to `tools/snapshots/buildings-<style>-<view>.jpg`; live at `localhost:8000/tools/buildings-gallery.html`. **Checks:** `test/building-kit.test.mjs` (determinism, regional mix, neighbour variety, dressing and annexes off the road and out of buildings, L/T cutting, presets, finite geometry).

**Cost on the Alpe (Balanced):** +1 to +13 draw calls and +0.02 to +0.15 M triangles at the fixed spots; about 1 s more at load (headless) for 7,000 buildings.

**Cost on Pittsburgh:**
- **High, busiest spots:** 8.8 km 307 calls / 2.24 M triangles (was 284 / 1.98 M); 17.3 km 343 / 2.16 M (was 322 / 1.95 M). The allowance is 2.5 M.
- **Load:** planning 8,200 homes adds about 1 s (headless).
- **Clipping QC:** the same findings as before.

## Rules for a new kit

1. **Opt-in by a scene field.** Add the field to `SCENE_FIELDS` in `scene-schema.js`, with its module, the keys inside it and a doc line. The linter and the gallery's field table pick it up from there.
2. **Data in the scene, not the code.** Names, distances, coordinates and species weights all belong in the scene JSON. Defaults should be generic.
3. **Build with `core/`.** Use `Builder` or `MeshBuilder` for geometry, `randomSequence(seed)` for anything random, and `roadFrame()` to place things by distance and side.
4. **Cheap by construction.**
   - Use instanced or merged draws, grouped by stretch of road and hidden past a reach.
   - Fade fine shader detail to its average under about 2 px.
   - Static meshes cast into the bake; moving ones set `userData.dynamic`.
5. **Every new kind of object gets a QC check:** course QC and clipping QC (see `claude/course-qc.md` and `claude/clipping-qc.md`).
6. **Models show in the gallery.** Put them in a pack, or list them in `meta.js`.
7. **Old names keep working.** If you rename a field, add it to `FIELD_ALIASES` and `normalizeScene`.

## Tools

| Command | What it does |
| --- | --- |
| `npm run new-route -- <id> --preset <biome>` | Starts a route (see above) |
| `npm run lint:scenes` | Checks every scene against the schema: unknown or misspelled fields (with "did you mean"), wrong types, unknown packs, fields on the wrong terrain, old names, and routes missing the standard look. Errors fail `npm test` |
| `npm run gallery` | Renders `tools/toolbox-gallery.html` to `tools/snapshots/toolbox-gallery.png`. | `npm run presets` | Rebuilds `routes/presets/` from the source routes |
| `npm run figures` | Bakes the figures' motion clips (`life/figures/rig.js`) into `life/figures/clips.js`. `npm test` fails if they're stale |
| `npm run snap:figures` | Renders the figures gallery (every clip, outfits, dogs, strollers, cyclists, every vehicle) to `tools/snapshots/figures-<view>.png` |
| `npm run guard -- record <dir>` then `npm run guard -- compare <a> <b>` | The refactor guard: renders fixed shots on every route with a frozen clock and seeded random, then compares PNGs pixel for pixel and every object's geometry, transforms and material. Run it before and after moving shared code |
| `python3 tools/fetch_osm_corridor.py <id>` then `python3 tools/build_places.py <id>` and `python3 tools/place_boards.py <id>` | Real places: fetches the map in a corridor along the route (OSM API tiles, cached), bakes land cover, buildings, lifts, power lines and dams into `routes/scenes/<id>-places.bin.gz`, and places town and col boards |
| `npm run snap`, `npm run qc`, `npm run qc:clipping` | As before (see `claude/scene-snapshots.md` and `claude/course-qc.md`) |

`npm run snap` also takes:
- `--png` and `--fingerprint`
- the shot tag `:standard`, which renders any route with the toolbox standard look (gentle look and baked light). The preview's `?standard=1` does the same.
